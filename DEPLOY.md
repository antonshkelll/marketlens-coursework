# Развёртывание MarketLens

Это учебный магазин на синтетических товарах и профилях. Он не принимает оплату и не должен собирать реальные контактные данные. GitHub Pages показывает статическую витрину; общие серверные заказы работают только в локальном или серверном режиме.

## Локально

Python 3.11+ и стандартная библиотека:

```sh
python experiment.py
python real_study.py
python -m unittest discover -s tests -v
python server.py
```

Открыть `http://127.0.0.1:8000`. `real_study.py` нужен для повторения исследования; для работы витрины достаточно уже включённого `docs/data.json`.

## Один сервер с Docker Compose

```sh
git clone https://github.com/antonshkelll/marketlens-coursework.git
cd marketlens-coursework
docker compose up -d --build
curl http://127.0.0.1:8000/api/health
docker compose logs --tail=100
```

Первое создание образа генерирует контрольную базу. Именованный том сохраняет SQLite между перезапусками. Не удаляйте том и не запускайте генератор поверх рабочей базы, если нужны созданные во время демонстрации заказы. У приложения включён WAL; записи выполняются транзакционно. Для нескольких экземпляров сервера с общей записью этот вариант не предназначен.

Перед внешней публикацией поставить HTTPS reverse proxy. В окружении приложения задать `MARKETLENS_ALLOWED_HOSTS=demo.example.org,localhost,127.0.0.1` со своим доменом (в Compose — через `environment`). Заголовок Host проверяется до обращения к базе; разрешайте только фактические домены. Создание выдачи выполняется только `POST /api/recommend` с JSON и проверкой Origin. Пример Caddy, после замены домена и хеша пароля:

```caddyfile
demo.example.org {
    request_body {
        max_size 16KB
    }
    basic_auth {
        student REPLACE_WITH_HASH
    }
    reverse_proxy 127.0.0.1:8000
}
```

Пароль и серверные ключи не записывать в репозиторий. Для открытой статической витрины пароль не нужен: она не пишет в серверную базу. Перед снятием защиты с серверной версии отдельно проверить ограничения частоты запросов и роста журнала, обработку ошибочных запросов, HTTPS и доступность только порта reverse proxy. В текущей версии профили демонстрационные и выбираются из списка: это не механизм аутентификации покупателей.

## Резервная копия

Для согласованной копии SQLite использовать backup API, а не копировать один основной файл при активном WAL:

```sh
docker compose exec -T marketlens python -c "import sqlite3; a=sqlite3.connect('/app/data/marketlens.sqlite'); b=sqlite3.connect('/app/data/backup.sqlite'); a.backup(b); b.close(); a.close()"
docker compose cp marketlens:/app/data/backup.sqlite ./backup.sqlite
```

Хранить резервные копии вне репозитория; периодически проверять восстановление на отдельной копии. Контроль работоспособности: `GET /api/health`; после обновления — просмотр карточки, добавление в корзину, демозаказ и запись в журнале. Для обновления: сохранить backup, выполнить `git pull`, затем `docker compose up -d --build` и повторить проверки.

Установка на внешний сервер ещё не выполнена. Домен, доступ и конкретные ограничения будут заданы при предоставлении сервера. Docker-конфигурация подготовлена, но контейнерный запуск не проверялся в текущей среде без Docker.
